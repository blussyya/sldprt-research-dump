# EXP-068 — BODY schema edit arithmetic explains the cross-era field gap

Date produced/captured: 2026-09-22. Base: staging `574fb8d02f30dc81a22128e599b19cc2a5b83d5c`.
Continuation of EXP-067 and predictions (a)/(d) in PARASOLID_XT_SPEC_NOTES.md.

## Method and reproduction

Source: this repository's published-spec notes, EXP-067, and its own 49 X_T corpus files.
Script: [body-schema-counts.js](scripts/EXP068/body-schema-counts.js).
Raw output and SHA-256 input hashes: [RESULTS.json](scripts/EXP068/RESULTS.json).

From repository root:

```sh
node knowledge/evidence/scripts/EXP068/body-schema-counts.js > /tmp/EXP068_RESULTS.json
```

No arguments uses repository root relative to the script; an optional first argument selects an explicit corpus root.
The runner independently reads length-delimited transmit description/schema, then the initial BODY edit script. It executes Copy/Delete/Insert/Append on symbolic base-field positions. It does not scan the entire text for declarations or decode an entity graph.

## Results

| Measurement | SW2011 | SW2022 |
|---|---:|---:|
| Files | 25 | 24 |
| Copy / Delete / Insert / Append | 23 / 0 / 0 / 4 | 22 / 1 / 6 / 7 |
| Base fields consumed (Copy + Delete) | 23 | 23 |
| Output fields (Copy + Insert + Append) | 27 | 35 |
| Stored field count immediately before edit script | 27 | 35 |
| Pointer gap measured before res_size | 6 | 9 |

All comparisons pass in all 49 files. Thus the two initial BODY scripts consume the same number of base fields and produce exactly their independently stored field counts.

More specifically, modern output inserts `lattice` (class 222), `mesh` (1006), and `polyline` (1008) before base field 7. EXP-067 places res_size at base field 7 (zero-based), after highest_node_id and six pointers. Applying the edit script moves that field to output position 10, exactly explaining the observed three-field increase. This predicts the gap from the edit instructions, rather than merely observing it.

The field reader also handles the observed zero-class scalar suffixes (element count 1, type d) and nonzero-class fields without that suffix. This corroborates the narrow initial-BODY omission pattern; it does not establish every field encoding or close NQ-042 globally.

## Falsification control

For every input, change the first BODY Copy opcode to Delete, parse the changed input again, and compare produced fields against the unchanged declaration. All 49 mutants produce one fewer field and fail the equality check. This tests sensitivity to an instruction change; it is not a hostile-file safety audit.

## Limits

- Only initial BODY scripts and the existing two-era corpus were tested.
- Base field identities come from EXP-067/spec notes; the remaining 23-field base layout is not reconstructed here.
- The parser deliberately rejects unobserved field flags, element counts, and scalar types.
- No pointer targets, node_id values, surfaces, curves, or topology were decoded.
- Stored field-count equality and the res_size shift corroborate the edit reading; they do not prove complete schema compatibility or BODY.highest_node_id semantics.
- No parser/viewer implementation changed; no invariant was promoted.
