# EXP-069 — Initial BODY declaration parity across binary and text exports

Date: 2026-09-26. Base: `staging` at `39095a36fbb65096e655d3a58651a1fc154b9eb2`.

Run from the repository root:

```sh
node knowledge/evidence/scripts/EXP069/body-binary-text.js
```

The [script](scripts/EXP069/body-binary-text.js) reads each `model.x_b` and `model.x_t` independently. It uses the existing bounded binary declaration-prefix reader from EXP-058 and a length-driven text reader that accepts both observed era preambles, then compares every initial named edit declaration through `Z` in order. [Raw results](scripts/EXP069/RESULTS.json) retain SHA-256 hashes of every input pair, offsets, root-field values and face counts from the SolidWorks build log.

| Export era | pairs | initial declarations per file | distinct declaration prefixes | binary/text declaration mismatches | binary–text root-field delta |
|---|---:|---:|---:|---:|---|
| SW2011 | 25 | 4 | 1 | 0 | 0 in 25/25 |
| SW2022 | 24 | 13 | 1 | 0 | equals logged native face count in 24/24 (counts 1–11) |

The 412 pairwise declaration comparisons are **two distinct prefixes**, not 412 independent schema observations. The result closes the specific NQ-041 gap for the *initial BODY prefix*: the prior text checker hard-coded `230` and failed on all SW2011 exports; this length-driven reader cross-checks both `186` and `230` preambles. It does not claim that every later declaration or every possible schema version is handled.

The post-`Z` binary scalar is read at the already identified `Z+3` position and compared with the first text BODY scalar. The differing modern values and equal legacy values reproduce the earlier observation through a paired binary/text parse. They do **not** reveal why the modern export's value differs by one per native face, and the `highest_node_id` interpretation still needs actual node IDs enumerated. No pointer target, entity, surface or curve has been decoded; no new invariant is promoted.
