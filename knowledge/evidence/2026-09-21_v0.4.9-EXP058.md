## Corrections to the previous brief and EXP-056

**19 is not the size of the initial contiguous declaration prefix.** The old text reader searches the whole transmit, so six of its matches occur later, after intervening numeric/record data. This experiment's text reader proceeds from the length-delimited header and stops at the first `Z`; it does not scan ahead for plausible names. The corresponding binary reader stops at that same marker. Do not extend the initial table to 19 by skipping arbitrary bytes.

**The alleged flag was not cross-validated.** All 312 initial export declarations have a stored binary word of `1` where the text reader sees `0`. EXP-056 compared only names/codes and used the minimum of the two table lengths; its successful test did not establish flag equality or table completeness. This result stores `storedFlagWord` and text `flag` separately. A biased numeric encoding is a possible explanation, not a decoded field semantics claim.

**This locates a prefix boundary, not a complete schema table or a decoded node stream.** The next binary byte is `Z`. Interpreting what follows, and how later declarations interleave with records, remains the next task. Historical EXP-056 source/results are unchanged.

## Method and failure controls

Two separate sequential readers consume text and binary declarations. Text header fields use declared string lengths: a digit regex would swallow the next numeric token because the schema identifier and following number are adjacent. The binary path reuses only the existing transmit-header reader. The nine-byte preamble is retained raw; its fixed size is a corpus-bounded assumption. Code-zero extension handling is also an observed-prefix rule, not a universal XT grammar.

Three controls pass: a truncated extension throws, a truncated header throws, and changing an extension byte changes the parsed result rather than silently preserving a match. Missing boundaries and unexpected declaration forms fail loudly. The readers do not recover by searching forward.

SLDPRT extraction uses the existing modern-container reader and the observed partition inner-zlib offset 28. That dependency is shared with earlier work; container independence is not claimed. No library, outside schema catalog, geometry expectation or external claim supplies declaration values.
