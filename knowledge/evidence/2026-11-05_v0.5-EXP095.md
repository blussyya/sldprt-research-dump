# EXP-095: duplicate modern-stream policy

The modern container reader currently stores streams in an object and silently keeps the first
nonempty occurrence of each name. NQ-033 asked for a deliberate duplicate policy. This experiment
checks whether the expanded corpus contains any valid duplicate names before proposing one.

The script and generated JSON are under `scripts/EXP095/`.

## No valid nonempty stream name is duplicated

The raw scan covers all 183 modern containers. It starts from the six-byte header signature, then
requires a printable decoded name, in-file bounds, successful inflation, the declared inflated
size, a nonempty payload, and the declared CRC-32.

> **Checked 2026-11-06 (EXP-097):** Correction: 178 modern containers. The 183 is every non-OLE2 path, including five files in `test files online/not-a-part/` that aren't SolidWorks containers (four STEP text files, one starting `nFJACwe0`). They hold no entries, so the other counts stand. A blind byte scan (`scripts/EXP097/blind-bounds-streams/`) reproduced 7,374, 521 and zero duplicates. The streams are raw DEFLATE.


| item | count |
|---|---:|
| raw signature candidates | 19,655 |
| valid nonempty entries | 7,374 |
| valid empty entries, excluded like the current reader | 521 |
| duplicate valid nonempty names | 0 |

The extra signature candidates are not duplicate streams. They are false header hits or records
that fail the bounded inflation, size, name, or CRC checks. After those checks, every nonempty name
is unique in every file.

## A conservative duplicate policy

The corpus supplies no evidence for first-occurrence or last-occurrence precedence. A reader can
avoid inventing one:

1. validate every candidate through inflated size and CRC before considering its name;
2. coalesce repeated names only when their inflated payloads are byte-identical;
3. reject a repeated name with different payload bytes as an ambiguous container.

The second and third steps are a defensive reader policy, not a recovered SolidWorks rule. They
preserve all information and fail explicitly if a future file presents a conflict. The current
corpus exercises neither duplicate branch.

## Reproduction

From the repository root:

```text
node knowledge/evidence/scripts/EXP095/duplicate-streams.js
```

A fresh blind scan independently repeated the entry validation and duplicate count.
