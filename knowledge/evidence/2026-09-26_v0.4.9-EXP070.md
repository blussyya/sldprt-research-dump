# EXP-070 — Paired BODY prefix values through precision fields

Date: 2026-09-26. Base: `staging` at `e60a19ed5444736c623362dd12337bc90722e106`.

From the repository root, run `node knowledge/evidence/scripts/EXP070/body-prefix-values.js`. The [script](scripts/EXP070/body-prefix-values.js) reads all 49 controlled X_B/X_T pairs; [raw output](scripts/EXP070/RESULTS.json) lists each model. EXP-069 retains input SHA-256 hashes for the same pairs. This test extends the initial BODY declaration comparison to its index, six (SW2011) or nine (SW2022) first pointer slots, and the following two precision fields. It does not decode the rest of the node.

| Export era | pairs agreeing on index and pointer slots | observed text pointer pattern | binary precision bytes |
|---|---:|---|---|
| SW2011 | 25/25 (6 slots) | `2,3,0,0,0,0` | `408f400000000001` / `3e45798ee2308c3a` |
| SW2022 | 24/24 (9 slots) | `2,3,0,0,0,0,0,0,0` | same |

Each observed binary pointer is a 16-bit big-endian value **one greater** than the corresponding text integer; the root index follows the same observed offset. The text `1e3` is `1000`, while the stored binary double is `1000.0000000000001` (one ULP higher); `1e-8` matches as a decoded double. Both pointer and precision-byte mutations break their respective checks.

This confirms alignment for the **single pointer pattern** repeated in this corpus, not the general encoding of all pointer indices or target node types. In particular, the BODY scalar differs between the two exports for modern files (EXP-069), even though these first pointers match. A typed record parser and traversal remain necessary to identify the pointer targets and compare surviving `node_id` values with `highest_node_id`. No new project-wide invariant is promoted.
