# EXP-092: small bounds and LocalBodies fields

EXP-091 left three questions that could be narrowed with existing files. This experiment decodes
the LocalBodies entry header, inventories the opaque ends of the per-face bounds record, and checks
every framed Parasolid payload in the one file whose configuration envelope is larger than its
display.

Scripts and generated JSON are under `scripts/EXP092/`.

## The LocalBodies entry header has a common ten-byte tail

All 281 entries use one of two layouts:

```text
old, 10 bytes: u32 flag | u8 0 | u32 first-section-size-plus-5 | u8 0
new, 18 bytes: u32 0 | u32 section-count | old ten-byte layout
```

The ten-byte layout occurs in 117 entries from 2017–2019. The 18-byte layout occurs in 164
entries, principally from 2020–2026. Its leading word is zero in every entry, and its section count
equals the observed count in all 164. That includes the two useful controls: one entry has two
sections and another has eight. Both padding bytes and every first-section size relationship match
in all 281 entries.

The size field is the section frame's leading `u32 size + 5`, or one more than the complete framed
section byte count. The ten-byte continuation record between later sections is the same common
layout with flag zero.

The flag is one in eight entries and zero in 273. All eight flag-one payloads that parse contain one
solid body, but flag zero also covers at least 150 solid entries, 116 sheet entries, and the two
multi-body controls. That correlation is not enough to name the flag. Seven payloads use a
Parasolid node type that the current XT reader does not support; this does not affect their bounded
header fields.

## The bounds head is fixed and one tail variant contains a unit vector

The survey uses 13,589 modern per-face records in 118 files whose following metadata parses. This
restriction matters: arithmetic searches also find configuration records and other data with the
same bounding-box relationships.

The three leading words are fixed at `[0, 0, 1]` in all 13,589 records. They are constants in this
sample, not face counts. The earlier list of several leading patterns came from arithmetic matches
that were not all parser-owned face records.

The tail at `+92…+131` has eight observed combinations of its five binary words. One state can be
described structurally:
when the words at `+104` and `+108` are both one, `+112…+127` contains four little-endian floats.
The last three form a unit vector in all 2,986 qualifying records; their norms range from
0.999999959 to 1.000000040. On all 2,406 cylindrical records, that vector is perpendicular to the
surface direction to within 2.83e-8 in absolute dot product.

This establishes a directional four-float variant, but it does not identify the first float or the
meaning of the direction on every surface family. Checks against saved vertex normals did not give
an exact scalar interpretation. The other flag states and the word at `+100` remain unnamed.

> **Checked 2026-11-06 (EXP-097):** "Surface direction" here is the display record's own axis. A blind check (`scripts/EXP097/blind-bounds-streams/`) could compare against the native B-rep axis on only 740 of the 2,406 cylinders; all 740 pass (max 2.82e-8). On 396 of them the vector points from the axis to the record's box centre, which is perpendicular to the axis anyway, so perpendicularity doesn't identify the vector.


## No readable Parasolid payload explains the larger configuration envelope

`ac760485_存矿小端.SLDPRT` records configuration bounds from
`(-0.004412333, 0, 0)` to `(0.15, 0.06, 0.112684250)` metres. Its display reaches approximately
`(0, 0, 0)` to `(0.15, 0.06, 0.1)`.

The file has eleven framed Parasolid sections. Ten parse as independent bodies: the active
38-face body, a zero-face GhostPartition with two points at the origin, and eight one-face
ResolvedFeatures support snapshots. Their combined point box is approximately `(0, 0, 0)` to
`(0.15, 0.06, 0.1)`. Sampling every decoded edge at 1,025 parameter values produces the same box
across 147,600 points. None reaches the configuration envelope. The remaining section is the
Partition delta program, which is not an independent body and requires its base schema.

The extra 4.412 mm in negative x and 12.684 mm in positive z do not appear in any readable section
point or the dense edge sample. The sampling is corroboration rather than an exact extremum proof.
A stale envelope, sketch/reference geometry, or another display-level object can still explain it.
The current feature reader stops before this file's sketches, so the evidence does not choose among
those possibilities.

## Reproduction

From the repository root:

```text
node knowledge/evidence/scripts/EXP092/localbodies-headers.js
node knowledge/evidence/scripts/EXP092/bounds-tail.js
node knowledge/evidence/scripts/EXP092/configuration-outlier.js
```

The JSON outputs retain every decoded header, per-file bounds counts, examples of every tail state,
aggregate unit-vector checks, and every section box. A fresh blind pass independently reproduced
all counts and the configuration edge sample.
