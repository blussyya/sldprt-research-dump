# EXP-080 — What SolidWorks 2022 does to a 2011 file when it saves it

Three files of the same 10 mm cube, from the controlled set:

| file | made by | how |
|---|---|---|
| `SW2011/C22_cube_sw2011_native` | SW2011 SP0, build d101004 (revision 19.0.0) | sketched and extruded in 2011 |
| `SW2022/C23_cube_sw2011_to_2022` | SW2022 SP0.1, build d220110 (revision 30.1.0) | C22 opened in 2022 and saved, no rebuild (build log) |
| `SW2022/C24_cube_sw2022_native` | SW2022, same build | the same cube made from scratch in 2022 |

C22 → C23 shows what the upgrade does. C23 → C24 shows what it leaves behind: everything in C23 that
differs from C24 apart from times and ids is 2011 state that survived the upgrade.

Tools, all in `knowledge/evidence/scripts/EXP079/`:

- `node compare.js A.SLDPRT B.SLDPRT` reads both feature trees and lists every field that exists in only
  one of them or has a different value, with top-level features paired by name.
- `node fieldtrace.js FILE` prints every field the reader takes, one line each, with its offset.
  Two traces can be diffed line by line.
- `load.js` reads either generation (SW2011 files get their first index recovered, see below).

All three files read strictly from the first byte to the last.

## 1. Container and streams

C22 is an OLE2 compound file with flat stream names. C23 and C24 use the 2022 container (the one
`package/src/container/modern` opens), with streams under `Contents/`, `_MO_VERSION_15000/`,
`_DL_VERSION_15000/`, `ThirdPty*/`, `docProps/` and `swXmlContents/`, and the OPC files
`[Content_Types].xml` and `_rels/.rels`. Every stream, compared by length and MD5:

| stream | C22 | C23 | C24 | what the upgrade did |
|---|---|---|---|---|
| ModelStamps | 12 | 12, **same bytes** | 12, differs | copied unchanged |
| OleItems, eModelLic | 4 | same | same | constant |
| DLUpdateStamp | 6 | same bytes (`_DL_VERSION_15000/`) | same | constant (`6a 00 00 00 00 00`) |
| CnfgObjs | 6 | 12 | 12 (same as C23) | strings rewritten as Unicode (§2) |
| CMgrHdr2 | 121 | 137 | 137 | 16 bytes of new fields (§2) |
| History | 101 | 129 (`_MO_VERSION_15000/`) | 101 | a second version entry appended (§2) |
| Biography | 1771 | 2719 (`_MO_VERSION_15000/`) | 1771 | grew; not decoded yet |
| Config-0-ResolvedFeatures | 8920 | 11481 | 11710 | rewritten in 2022 class layouts (§3) |
| Config-0 | 18791 | 25244 | 24626 | rewritten; not decoded yet |
| Config-0-Partition | 3292 | 3479 | 3470 | Parasolid body re-sent by the 2022 modeller (§4) |
| Config-0-GhostPartition | 521 | 636 | 635 | same |
| Config-0-LWDATA, CMgr, Definition, Header2 | | rewritten | | not decoded yet |
| Config-0-ModelHeader | – | 2459 | 2307 | new stream. In C23 it is byte-identical to Header2; in C24 the two differ |
| DisplayLists, Preview, PreviewPNG | | regenerated | | |
| DocumentSummaryInformation, SummaryInformation, ISolidWorksInformation, Config-0-Properties | yes | – | – | moved into `docProps/*.xml` |
| Features, KeyWords (`__ZLB`) | yes | – | – | replaced by `swXmlContents/Features`, `swXmlContents/KeyWords` (XML) |
| Tables, AssyVisualData, VisualStates | yes | – | – | dropped or moved (`ThirdPtyStore/VisualStates`) |
| ThirdPtyStore/ThirdPtySTGStore | – | 1540 | – | **only in the upgraded file**: an empty OLE2 compound file (a Root Entry and nothing else) |
| 3DExperienceExchange2, PMISemanticDataDB, SwDocContentMgrInfo, ThirdPty/Animator, ThirdPty/CMMotionLoadMapU, CusProps, docProps/*, swXmlContents/* | – | yes | yes | new in 2022, written for every file |

The docProps carry the upgrade's history in plain text. `core.xml` of C23 has `created`
2026-09-21T09:41:35Z (the 2011 file's creation) and `modified` 09:43:31Z (the 2022 save).
`OpenTime.xml` has `count` 1 and `FileOpenTime` 0:09 (the file was open for 9 s in 2022), where C24
has `count` 0. `Config-0-Properties.xml` of C23 keeps a DocumentSummaryInformation code-page property
(65001) that came from the 2011 property set; C24 has none.

## 2. Small streams, byte by byte

**ModelStamps** (12 bytes): u32 time, u32 0x6a, u32 0x67. C22 and C23 both hold 0x6ab0fbcd
(09:41:33, the last 2011 rebuild). The upgrade copies it because it does not rebuild. C24 holds its own
time.

**CnfgObjs**: u32 0 followed by two empty strings. SW2011 writes the strings as ANSI CStrings (one
length byte, `00`): 6 bytes. SW2022 writes them as Unicode CStrings (`ff fe ff 00`): 12 bytes.

**CMgrHdr2** (class dmConfigMgrHeader_c / dmConfigHeader_c, configuration "Default"): identical up to the
flags word `00 80 01 40`. After it:

| | bytes |
|---|---|
| C22 | `00`, u32 time 0x6ab0fbd2 (09:41:38) |
| C23 | `80`, u32 0, u32 101, u32 101, u32 time 0x6ab0fc43 (09:43:31, the 2022 save), u32 2 |
| C24 | `80`, u32 0, u32 102, u32 101, u32 time, u32 2 |

The byte before the time is 0x00 in 2011 and 0x80 in 2022, and the 2022 form adds four u32.

**History**: moVersionHistory_c is a counted list of saves (u32 count). Each entry is u32, u16, u32
unix time, a string, u32 SolidWorks version and a moDateCodeHistory_c object (u32 1, u32 whose low 24
bits are the build date code and whose top byte is a flag). The list ends with u32 0, i32 −1 and 14
zero bytes.

| | entries |
|---|---|
| C22 | (0, 0, 01:58:55, "", **4700**, date code **2010276**, 1) |
| C23 | the same entry, then (**3**, 0, 09:43:11, "", **15000**, date code **2022009**, **0**) |
| C24 | (0, 0, 2026-08-12, "", 15000, 2022009, 1) |

The date code is YYYYDDD: 2010276 is day 276 of 2010 (the build is dated 2010-10-04), and 2022009 is
day 9 of 2022. The flag (the last number in each row) is 1 on the version the file was **created** in
and 0 on a version that only re-saved it. The leading u32 is 3 on the upgrade entry; what it counts is open. The 01:58:55
and 2026-08-12 times match the default planes' creation stamps (see below), so they are the
template's creation, not the part's.

## 3. The feature tree (Config-0-ResolvedFeatures)

### 3.1 Stream framing

| | C22 | C23 | C24 |
|---|---|---|---|
| first u32 (first index) | absent | 108 | 109 |
| u16 slot count | 15 | 19 | 19 |
| objects read | 15 (slot 5 null) | 18, then the stream ends | 19 (the last one null), then u16 0 |

SW2011 does not write the first index. The archive still continues Config-0's (the node class is
pre-loaded at index 64 in C22), and `load.js` recovers the index: 162 for C22 (§3.4).

In C22 the null is slot 5, where SW2022 puts the Markups folder. The upgrade adds four folders and fills
that slot, so 15 + 4 = 19 slots are declared but only 18 objects are written. The upgraded stream also
lacks the null slot and the trailing u16 that every native SW2022 stream ends with. A reader has to stop
at the end of the stream, not trust the count.

### 3.2 Every object is re-written in the 2022 class layout

The upgrade re-serialises every object with the 2022 schema. These are the layout differences between
the generations, as the reader now handles them (`r.legacy` in `archive.js` / `classes.js`):

| class | SW2011 | SW2022 |
|---|---|---|
| feature node (pre-loaded) | name, a, flags, id; short form (parameters): u16; else u32 b, u16 d, children … | name, a, flags, id, u32 b, comment string; short form: u16; else u32 c, u16 d, children … |
| node tail | 54 bytes, u16 2, u32 state | 54 bytes, u16 2, **four u16**, u32 state |
| folders (Comments, Sensors, Design Binder, Equations, Markups) | nothing after the node | u32 |
| Annotations | u16, f64 1.0, f64 1.0 | the same and 10 bytes |
| Surface / Solid Bodies | 10 bytes | 16 bytes |
| Material | name | u32, name, u32 |
| reference plane | 140 bytes, data | 150 bytes (4 more before the size doubles, 6 at the end), data |
| default plane data | 88 display bytes | 96 (8 zero bytes at the end) |
| component (pre-loaded) | 43 bytes | 79 bytes: the same and 16 × `ff`, 20 bytes |
| sketch attribute block | 35, object, **19** | 35, object, **27** (8 zero bytes after the f64 1.0) |
| sketch handles (point, line) | u16, i32 | u16, i32, u32 |
| sketch relation | 8, i32 −1, 14 bytes, type, u32 2, u16, u16, i16 −2, u16, handles | 8, i32 −1, 16 bytes, type, u32 2, u16, i16 −2, u16, handles |
| sketch | 8 bytes after the first object list; 13 next-id counters; three u32 and a u16; 10 bytes after the regions slot | 12 bytes; 14 counters; four u32; 30 bytes |
| profile tail | 8 bytes | 12 bytes |
| reference to outside geometry (moSketchExtRef_w) | 34-byte block (two i32 −12345, version at offset 30), 10 bytes, name | 52-byte block (three i32 −12345, version at offset 34), then by version (§3.3) |
| document object (moExtObject_c) | **pre-loaded from Config-0**, path and name strings are Config-0 objects (refs 61, 62); one string, 16 bytes | defined in this stream with its two string objects; three strings, u16, the same 16 bytes |
| face name tail | 6 bytes | 18 bytes, with the version at offset 6 |
| feature data (pre-loaded) | u32, 58 bytes | u32, 62 bytes |
| displayed dimension | 374 bytes of settings | 556: 182 bytes inserted at offset 236 |
| dimension handle | 63 bytes | 103 bytes |
| displayed dimension, after the favourite | 248 bytes | 374 |
| extrusion end | 19 bytes, u32, 4 bytes | 19 bytes, u32, 8 bytes |

### 3.3 Values the upgrade carries over from 2011

These are in C23 exactly as in C22, and differ from the native C24:

- **Version stamps in every feature node**: created and modified stay 4700 / 2010276. A native
  2022 feature has 15000 / 2022009.
- **The generation byte**. The node tail starts `00 ff ff 00 00 0g`, and every sketch attribute block
  starts `ff ff mm 00 0g`, with g = 1 and mask mm = 0x07 for 2011-made objects, against g = 3 and
  mm = 0x1f for 2022 ones. The displayed-dimension settings carry the same `ff ff 00 00 0g`. Byte 32
  of the node tail is 0 for 2011-made objects and 1 for objects made by 2022 (natively or added by the
  upgrade).
- **References to outside geometry** keep version 4700. The upgrade re-writes them in the 52-byte form
  but, because the version is below 15000, follows them with u32 0, u32 0 and the entity's name
  ("Point1@Origin") instead of the backed-up copy object a native file has.
- **Face names** keep 4700 in their tail, where a native file has 15000.
- **Sketch regions** stay null. SW2011 doesn't store them; a native 2022 sketch lists its closed
  regions. This is the clearest sign that the sketch was not recomputed.
- **Feature ids and creation times** (KeyWords ids 18 Sketch1, 24 Boss-Extrude1; feature stamps
  09:41:37, plane stamps 01:58:54) are kept, so the names of faces and edges (moFR_c: feature id and
  time) still resolve.
- **The extrusion's feature data** (first u32 6, native 5), the end condition's moFromEndSpec_c bytes,
  and byte 3 of the dimension placement (0x13, native 0x1b).

### 3.4 Values the upgrade sets

- **Four new folders**: Favorites, History, Selection Sets and Markups, plus the two Notes folders
  inside Annotations. They take fresh ids after the highest 2011 id (Notes 25 and 26, Markups 29,
  Favorites 30, History 31, Selection Sets 32), created version 0, modified 15000 / 2022009, generation
  3, and the tail u16s 0, 0, 1, 0.
- **The four u16 SW2022 adds to every node tail** are 0x097c, 5, 1, 0 in a native file and 0, 0, 1, 0
  on everything the upgrade carried over or created. That makes them a reliable "came through an
  upgrade" mark.
- **Bit 31 of the node flags** is set on the user features (Sketch1 0x40000000 → 0xc0000000,
  Boss-Extrude1 0x40000140 → 0xc0000140) and on nothing else. Native features don't have it. Likely
  "made in an older version, not rebuilt yet": to confirm with a file upgraded and then rebuilt.
- **The sketch's last misc u32** (2011: a u16 0) becomes 1; native 0.
- **Byte 9 of the displayed-dimension settings** becomes 0x20; 0x00 in both C22 and C24.
- **The extrusion's first code pair** goes from (1, 0x75) to (1, 0x3a), the value native files use.
- **The document object** (moExtObject_c), which SW2011 kept in Config-0, is written into the feature
  stream with the **full path of the 2011 file it was opened from**
  (`D:\projects\sldprt research dump\new test files\sw2011\C22_cube_sw2011_native\model.SLDPRT`) and
  document name "model". Its stamp is 09:41:33 (the 2011 ModelStamps time), and its trailing bytes keep
  0x5f and 0x3c where C24 has zeros. A native file has an empty path and the name of the
  unsaved document ("Part43").
- **The Sensors folder's FILETIME**, all zero in 2011, is filled in.

### 3.5 Stream framing differences, summed up

C22 (8920 bytes) to C23 (11481 bytes): +2561 bytes. Most of it is per-object schema growth (§3.2),
the six new folders, and the document object and its path moving in from Config-0.

## 4. Geometry

The Parasolid body is re-transmitted by the 2022 modeller (schema `SCH_3301247_33103`, modeller
3301247) even though the feature tree was not rebuilt; C22 has `SCH_2201236_20000`. The partition,
deltas and ghost sections of C23 have the same lengths as C24's (6118, 1096, 1109 bytes), with 918, 254
and 2 bytes differing. The solid is unchanged (1000 mm³, six planes, per the build log).

## Open

- Bit 31 of the node flags: needs C22 saved in 2022 after a full rebuild (Ctrl+Q). Postponed until a
  SolidWorks machine is available again (2026-10-05).
- History's leading u32 (3 on the upgrade entry).
