# EXP-094: active geometry without ModelHeader

EXP-084 found twelve modern files with `Config-N-Partition` streams but no
`Config-N-ModelHeader`. Six have one configuration and need no choice. The other six were left on
a lowest-number fallback. This experiment tests that fallback against the saved display geometry.

The script and generated JSON are under `scripts/EXP094/`.

## The saved analytic display bounds select one geometry in every file

For each multi-configuration file, the script first keeps partitions whose native face count
equals the saved display face count. It then compares the union of the saved per-face analytic
bounds with a candidate box built from every native vertex and 257 parameter samples on every
decoded edge.

| file | configuration IDs matching the display box |
|---|---|
| `118a3cb0_cut-z18-b1xh1xl1` | 268 |
| `289756ce_cut-z071-b1-l1-l2-typ` | 21 |
| `629adcec_cut-z351-d1xl1` | 0, 1, 4 |
| `70477058_mt-cut-z085-l1xb1-typ` | 0, 1, 4 |
| `516a7dc5_Body1` | 0, 1 |
| `afc71d14_Body2` | 0, 1 |

Every listed match equals the display box within 1e-8 m; in practice every reported box error is
zero at the stored double values. The closest rejected candidate differs by 0.1 mm. The sampling
is not an analytic extremum proof, but that margin and the exact matches make the selection
discriminating on this corpus.

A blind check repeated the comparison with 513 samples per edge and recovered the same sets. The
relevant faces are planes, cylinders, and cones; none introduces a spline-surface interior extremum.

## Tied IDs contain the same conversion geometry

Each matching partition is converted independently to the project's exact native STEP output.
After replacing the generated header timestamp, tied candidates have identical STEP bytes within
each file. Thus the four files with several matching IDs retain an ambiguous active configuration
name, but not an ambiguous conversion shape.

The lowest-number fallback is outside the matching set in two files:

- `cut-z18` currently chooses 0; the saved display selects 268. Their boxes differ by 56 mm.
- `cut-z071` currently chooses 1; the saved display selects 21. Their boxes differ by 0.1 mm.

In the other four files, the lowest ID belongs to the one matching geometry group. Across all six
multi-configuration files, display face count plus saved analytic bounds therefore selects exactly
one native geometry, even when it cannot recover the configuration's name.

## Reproduction and limit

From the repository root:

```text
node knowledge/evidence/scripts/EXP094/legacy-active-geometry.js
```

This is a corpus-backed selection rule for conversion. It does not decode an older active-ID field,
and it does not claim that dense edge sampling proves exact extrema for an arbitrary future curve.
A fresh blind pass independently checked the six candidate sets and normalized STEP equality.
