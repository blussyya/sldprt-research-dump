# EXP-081 — Config-0, the configuration archive

Config-0 is the first stream of a configuration and the one the feature tree (Config-0-ResolvedFeatures)
continues. It reads to its last byte in all 49 controlled models (25 SW2011, 24 SW2022), with
`knowledge/evidence/scripts/EXP079/config0.js`:

```
node probe0.js "<model.SLDPRT>"        # reads Config-0, prints where its index sequence ends
STREAM=Config-0 node fieldtrace.js "<model.SLDPRT>"   # every field with its offset (START=1 for SW2011)
```

## The check that proves the reading

Config-0 is an MFC CArchive, and ResolvedFeatures carries on its index sequence (classes and objects
share one counter). So the counter Config-0 ends on must be exactly the first index of the feature
stream: SW2022 writes that number as the feature stream's first u32, and for SW2011 it was recovered
from the feature stream alone (EXP-079). In all 49 files the two agree. A missed or invented object
anywhere in Config-0 would shift the count, so this checks the object structure end to end. The
SW2011 first index is now read from Config-0 (`load.js`, `probe.js`); the inference stays as a fallback
(`INFER=1`) and gives the same number for all 25 files.

The archive starts at index 2 in SW2022 files (1 is mapped in advance) and at index 1 in SW2011 ones.
Its classes are the "pre-loaded" classes the feature stream refers to:

| feature stream role | class | SW2022 index | SW2011 index (C22) |
|---|---|---|---|
| feature node | moNodeName_c | 4 | 64 |
| component | moUnitComponent_c | 43 | 102 |
| object list | suObList | 82 | 8 |
| per-feature data object | moPMarkRecord_c | 102 (103 when the file has two annotation views) | 160 |
| document object | moExtObject_c (+ moCStringHandle_c) | defined in the feature stream | 58 (60) |

The per-feature data object is a PMI mark record. Inside features it has version 5–10 and 62 bytes
after the version (58 in SW2011); Config-0's own instance has version 3, or 4 in the upgraded file and in
SW2011, with the layout below. The component class is read with 79 bytes in the feature stream, but
Config-0's own instance has 10; why they differ is open.

What SW2011 files keep in the header (the feature log with each feature's Created / Modified times,
the authors, the document object and its path) is not in SW2022's Config-0. In SW2022 the document
object moves into the feature stream (EXP-080), and the log presumably into the Biography stream
(not decoded yet).

## Document properties (moRelMgr_c), not split yet

The block holds the drafting standard: unit names (m, mm, cm, km, um, µm, nm, s, Hz, Pa), then nine
dimension-style records (each with an inline length unit, its dual unit as a new moLengthUserUnits_c
object, an inline angle unit, the font "Century Gothic" with height 0.0035, and two "CONTINUOUS" line
styles), about fifty further font records (notes, balloons, tables …), SW2022's "Segoe UI" records,
and the cut-list templates ("%Description%  %MATERIAL%  %LENGTH% …"). SW2011's version has "Visible"
line styles and "Invalid FontFace" records instead. Until the records are decoded the reader steps
over the bytes and reads each embedded unit object where it sits (a new-object tag of the length-unit
class followed by a valid unit). The index check above shows that no other object hides there.
