# EXP-093: configuration-envelope version boundary

EXP-091 found the named configuration envelope in 113 of 166 readable modern DisplayLists
streams, but did not explain why older files omit it. This experiment compares that result with the
declared DisplayLists version and coarse configuration structure.

The script and generated JSON are under `scripts/EXP093/`.

## The named record starts at DisplayLists version 13000

The corpus has a clean observed boundary:

| declared DisplayLists version | files | files with named envelope |
|---:|---:|---:|
| 3800–12000 | 42 | 0 |
| 13000 | 8 | 8 |
| 14000 | 5 | 5 |
| 15000–19000 | 111 | 100 |

Version 13000 is the first version with the record. None of the 42 files at version 12000 or below
has EXP-091's relationship between an MFC UTF-16 configuration name and the 132-byte envelope.
Five have an extra arithmetic bounding-box match, but none has the name relationship; arithmetic
shape alone is not a configuration-record signature.

EXP-085 established that the declared version belongs to the release that last wrote the
DisplayLists stream, even when a later SolidWorks release saved the surrounding file. That explains
why a recent file can retain an older layout without this record.

## The record is common rather than mandatory after the boundary

Of 124 files at version 13000 or later, 113 have the named envelope. Three of the eleven omissions
have no parsed display faces, leaving eight comparable omissions among 121 files with faces.

Coarse structure separates the simplest case:

| version 13000+, parsed faces | files | with envelope |
|---|---:|---:|
| one configuration ID, no LocalBodies | 97 | 97 |
| one configuration ID, LocalBodies present | 21 | 15 |
| multiple configuration IDs, no LocalBodies | 2 | 1 |
| multiple configuration IDs, LocalBodies present | 1 | 0 |

LocalBodies or multiple configuration IDs account for all eight readable omissions, but neither
property is sufficient to suppress the record. Fifteen LocalBodies files and one multi-configuration
file still carry it. The corpus therefore supports an introduction boundary and an association,
not a complete post-13000 inclusion rule.

## Reproduction and limit

From the repository root:

```text
node knowledge/evidence/scripts/EXP093/configuration-presence.js
```

The result inherits EXP-091's bounded name signature. It does not treat a free-standing arithmetic
lookalike as a configuration envelope. A fresh blind pass independently repeated the version and
structure counts.

> **Checked 2026-11-06 (EXP-097):** That pass left no script. A new blind check (`scripts/EXP097/blind-config-envelope/`) repeated the counts. Re-saves don't explain the omissions either: 3 of the 8 were saved by one release only, and 34 files saved by several releases keep the record (`scripts/EXP097/resave/`).
