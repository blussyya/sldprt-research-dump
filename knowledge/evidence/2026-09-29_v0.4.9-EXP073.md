# EXP-073 — Original corpus primary partition audit

Captured 2026-09-29 UTC. Base: staging `0df1dadfbaa1daec390c9351eb3b82f7aea8ad4f`. Run `node knowledge/evidence/scripts/EXP073/original-partitions.js --write`. [Source](scripts/EXP073/original-partitions.js) and [raw results](scripts/EXP073/RESULTS.json) preserve all file hashes, type counts, byte coverage, unresolved references, and new embedded schemas.

Of 24 original SLDPRT inputs, the 21 modern files have their first `Config-0-Partition` payload parsed through EOF: **38,825 typed nodes, 1,146 faces, 82,598 passing graph checks**. This includes the external gear, duck, Pocket Wheel, distributor, and both USB housings, in addition to the original controlled files. Every byte of each inflated payload falls in a recorded typed range. Complete schema-described structure does not establish all semantics or independently validate every surface mathematically.

The reader additionally handles full embedded declarations, including `INTERSECTION_DATA`, without guessing its field layout from a signature scan. Field descriptors and observed values are preserved; the meaning of any undeclared enum values remains open. Supporting types added for this corpus include intersection charts/limits, rolling-ball blends, blend boundaries, swept surfaces and unicode value records.

One important counterexample: PTC GE8080-8's primary payload contains only WORLD and **zero faces**, while its saved DisplayLists has **126 faces**. Hence primary-partition decoding alone is not a general saved-body selection rule. No GhostPartition or delta reconstruction was performed here.

SW2000-s01, chainwheel and plate4 are blocked because they lack the selected `Config-0-Partition` stream. Their legacy stream inventories differ: the first two use `DisplayLists__Zip`; plate4 has uncompressed `DisplayLists`. This experiment does not decode those alternative B-rep wrappers. Their original bytes are unchanged.
