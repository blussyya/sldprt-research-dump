## Part A. How SolidWorks writes what STEP can't express

EXP-078 wrote intersection curves and rolling-ball blends as B-splines, because STEP has no exact
form for either. Question: what does SolidWorks' own STEP export do with them, and should ours
follow it?

The only real parts in the corpus with a SolidWorks STEP are the two USB hub halves. They are the
same model as the SLDPRT: all 82 (TOP) and all native vertices of BOTTOM coincide with STEP
vertices to 3.5e-18 m; the extra STEP vertices are seam splits.

| | SolidWorks' STEP | ours (EXP-078) | ours (now) |
|---|---|---|---|
| declared uncertainty | 1e-5 mm (10 nm) | 1e-8 × unit | same |
| intersection / tolerant edge curves | cubic B-splines, knot multiplicities 4, 2, …, 2, 4; worst 0.98 µm (TOP), 0.86 µm (BOTTOM) from the true curve | cubic, multiplicity 3, within 1e-9 m | multiplicity 2, same curves (removing the redundant point moves the curve by 4.5e-16 m) |
| curve control points (TOP, 22 curves) | 208 | | 1,540 |
| B_SURFACE faces | copied (rational 2×3, 3×10) | copied | copied |
| rolling-ball blend (TOP, 1 face) | rational B-spline, degree 3 along the spine × 2 across, 10 × 3 points; about 1.5e-7 m off | bicubic, 33 × 25 points, within 1e-8 m | rational, degree 3 × 2, 17 × 3 points, within 1.5e-9 m |
| volume vs the exact body | +0.0205 mm³ (TOP), +0.0190 mm³ (BOTTOM) | exact | exact |
| file size | 241 KB (TOP), 142 KB (BOTTOM) | | 177 KB, 84 KB |

So SolidWorks approximates exactly where we do, at about 1 µm on curves and 0.15 µm on blends, and
its own STEP is not the exact body (its volume is off by 2–3 parts per million).

One choice of SolidWorks' is better than ours was: across a blend it writes a **rational quadratic**,
which is the exact circular arc, and approximates only along the spine. The package now does the
same (`blendSurfaceRational` in `src/brep/blend.js`): exact cross-sections interpolated in
homogeneous coordinates along the spine, with sections added until the surface is within 1e-8 m of
the blend. A point is on the exact blend when it is |range| from the spine (the envelope of the
rolling ball) and the two boundary rows lie on the supports; that is what is checked.

| part | blend faces | form | worst deviation | control points per face | before |
|---|---|---|---|---|---|
| USB hub TOP | 1 | rational arc × cubic | 1.5e-9 m | 51 | 825 |
| Pocket Wheel | 32 | rational arc × cubic | 8.7e-9 m | 99 | about 1,900 |

Checks after the change: both parts round-trip; OpenCascade reads TOP, Pocket Wheel, chainwheel and
Dekor as one valid solid each; our volumes are unchanged to 3e-10 relative and OpenCascade's
analytic volume of Pocket Wheel now agrees with ours to 1.5e-9 (was 2e-9).

## Part B. The feature tree stream (in progress)

Notes kept as the reader is built; to be completed.

- The tree is in `Config-N-ResolvedFeatures` (modern and SW2011). It is an MFC `CArchive` object
  stream: `FFFF` + schema + name for a new class, `0x8000 | k` for a new object of class k, plain
  `k` for an object already read. Classes and objects share one index sequence.
- Modern files: the stream starts u32 N, u16 M. The index sequence starts at N + 3 (C00 109 → 112,
  C03 110 → 113, Dekor 180 → 183, distributor 238 → 241, every modern file); M is the number of
  top-level objects (19 in C00). Indices below the start refer to objects of an earlier archive
  (e.g. object 70 from the Solid Bodies folder). SW2011 files start with u16 M directly.
- `swXmlContents/KeyWords` (modern) is a plain XML index of the tree: every feature's id, name and
  type, and some dimension values (C04: Boss-Extrude1, D1 = 10).
- Every feature object starts with a nested object of class #4 (modern) holding the name (UTF-16
  MFC string), flags, the feature id (equal to the KeyWords id on every feature checked: planes
  2/3/4, Origin 5, Sketch1 26, Boss-Extrude1 32, Sketch2 33, Cut-Extrude1 46), a comment, a list
  of object references (an extrude's references include its sketch), an order number, created and
  modified version/build stamps (15000 / 2022009) and a FILETIME.
- About 160 classes occur in the stream across the corpus; the controlled models use about 60.
