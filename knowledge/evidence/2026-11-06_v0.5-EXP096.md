# EXP-096: the LocalBodies exclusion flag

EXP-092 decoded the two LocalBodies entry-header layouts but left their shared `u32 flag` unnamed.
This experiment joins that flag to attributes inside each entry's Parasolid body.

The script and generated JSON are under `scripts/EXP096/`.

## The flag mirrors BODY_IN_LIGHTWEIGHT_PERM exclusion

EXP-084 established the body-level rule: `BODY_IN_LIGHTWEIGHT_PERM=0` excludes an imported body
from the finished part, while value 1 includes it and a missing attribute behaves as included. The
LocalBodies header flag follows the inverse inclusion state exactly on every readable payload:

| header/body state | bodies |
|---|---:|
| flag 1, explicit body attribute 0 | 8 |
| flag 0, explicit body attribute 1 | 258 |
| flag 0, body attribute absent | 16 |
| contradictions | 0 |

The survey covers all 281 entries. Seven flag-0 entries use Parasolid node type 68 without a base
schema in the current XT reader, leaving 274 decoded entries and 282 decoded bodies. The extra body
count comes from the entries with two and eight sections. Every body in those multi-section entries
has the included state.

All eight flag-1 entries are solid import bodies already shown by EXP-084 to be left out of the
displayed finished part: imports in the pin files, `51065319`, `db8a97e2`, and `d0d61cde`. The
header field can therefore be named an excluded-from-lightweight-permanent-body-set flag for the
tested corpus. “Consumed” describes some examples but is not proven as the reason for every
exclusion. The verified serialization rule is:

```text
entry flag = 1  iff  BODY_IN_LIGHTWEIGHT_PERM is explicitly 0
entry flag = 0  when BODY_IN_LIGHTWEIGHT_PERM is 1 or absent
```

## Reproduction and limit

From the repository root:

```text
node knowledge/evidence/scripts/EXP096/localbodies-flag.js
```

The seven unread payloads are all flag zero, so they cannot contradict the observed flag-one rule
but could add another flag-zero attribute case. A fresh blind pass independently resolved the
attribute definitions and checked the join; it also confirmed all ten bodies in the two
multi-section entries use the included-by-default missing-attribute case.
