# EXP-083 — Which SolidWorks release saved a part

**Question.** Can the saving release (and the creating one) be read from the file alone, for every
container from SolidWorks 97 to 2026?

**Answer.** Yes. The last-saved release code is in the `_MO_VERSION_<n>` name; the `History`
stream (moVersionHistory_c, first described in EXP-080) lists every save with its release code
and the build date of that release. Read on all 73 unique corpus parts, 0 errors. Write-up:
[sldprt-format-research/format/6-version-history.md](https://github.com/blussyya/sldprt-format-research/blob/main/format/6-version-history.md).
Reader: `solidworks-converters/src/container/history.js`, tests in `test/history.test.js`.

## Release codes

From SolidWorks' API help (`IModelDoc2::VersionHistory`, `ISldWorks::GetLatestSupportedFileVersion`):
95 = 44, 98 = 822, 2000 = 1500, 2001 = 1750, 2001 Plus = 1950, 2003 = 2200, 2007 = 3400,
2008 = 3800, 2009 = 4100, 2010 = 4400, 2011 = 4700, 2012 = 5000, then 2013 = 6000 and +1000 a
year (2022 = 15000, 2026 = 19000). No rows found for 96, 97, 2004–2006.

## Findings

1. **`_MO_VERSION_<n>` is a storage in OLE2 files**, not a stream (type 1, size 0). Filtering the
   directory to streams loses it; read all entry names.
2. **History layout** (little-endian): class header, u32 count, then per save u32, u16, u32 unix
   time, string, u32 release code, moDateCodeHistory_c (full class header first time, u16 class
   reference with the top bit set after), u32 k, k × u32 date codes (low 24 bits YYYYDDD, top byte
   1 on the creating release).
3. **Strings before 2001 are 8-bit.** SW2000-s01 (1500): u8 count + 8-bit chars, no `ff fe ff`.
   The first reader failed there ("expected a string at byte 39").
4. **k is not always 1.** plate4 (629, 1997): its second save carries two date codes, 1997/203 and
   1997/205. Reading a fixed single u32 desynchronises the rest of the stream.
5. **Build dates agree with the codes**: 12000 built 2019/304, 14000 2021/301 and 2020/273,
   15000 2022/009, 16000 2023/096, 17000 2024/078 and 2024/157, 4700 2010/276, 1950 2001/340,
   1500 2000/268.

7. **Beyond the corpus.** 141 openly published parts from 67 GitHub repositories (Git LFS) read with
   the same reader: saves from 2007, 2010, 2011 and every year 2013–2026 (8 files at 19000, 15 at
   18000). None from 2008, 2009 or 2012 yet. Conversion of these is a separate check, still open.
