# EXP-090: audit the next-question queue and run its missing split-line control

`NEXT_QUESTIONS.md` had accumulated historical work under live-looking `Active`, `Ready` and
`Blocked` labels. This experiment checks those labels against EXP-042 through EXP-089 and runs the
one old proposed control that later appeared in the corpus.

## The queue was stale

The audit found four broad groups:

- EXP-042–046 decoded Block1 as strip-edge annotations. That retires the old SMALL/LARGE grammar,
  token-signature, face-orientation and global-state questions. Their correlations were patterns in
  topology and edge-ID allocation.
- Several requested inputs arrived later. C11 supplies the third hole diameter; C13–C21 supply the
  curved controls; C18 supplies the split line; the expanded online sample supplies nonzero Block3.
- Several implementation questions were completed but their first entry stayed open: analytic STEP,
  native node enumeration, legacy OLE2, metadata retention and CRC checks.
- A smaller set is genuinely open. It is now listed near the top of `NEXT_QUESTIONS.md`, separated
  into work possible with the current corpus and work blocked on a discriminating file or save.

A blind audit, performed without editing the file, independently classified the same stale groups
and kept the same unresolved core: optional scalar semantics, display edge-type records,
configuration selection without ModelHeader, remaining off-surface vertices, zero-normal support,
and Block3 strip controls.

## C18 answers NQ-029

NQ-029 asked for a split line across one cube face so adjacency to a new face could be separated
from changing the neighboring face's own boundary. It said that model did not exist. C18 was added
later in both the SW2011 and SW2022 control sets.

C18's line crosses the top at `y = 0.005`. The `y = 0` side has the decisive change: its top
neighbor becomes the newly created lower top face, while the side keeps the same four vertices,
four edge IDs, strip length and raw Block1 sequence.

| era | side face | old/new neighbor | unchanged raw Block1 |
|---|---:|---:|---|
| SW2011 | 83 | face 1 -> new face 143 | `1,7,76,0,77,53` |
| SW2022 | 88 | face 1 -> new face 148 | `1,9,81,0,82,58` |

The two `x` sides are the positive control. The split reaches their top edge, adds a midpoint and
one native edge ID, and grows each Block1 array from six to eight words. The other `y` side keeps
its old boundary and Block1 while remaining beside the retained top half.

Every parsed array matches the raw DisplayLists words. A fresh blind check independently recovered
the same split, face IDs, edge sets and byte sequences. This closes the proposed test: adjacency to
a newly created face is not sufficient to change Block1 in this construction; modifying the face's
own boundary is sufficient here. It does not establish a universal rule for every feature.

Evidence: `scripts/EXP090/split-line/`.

## Current work exposed by the audit

The highest-value format work that needs no new files is now:

1. active-configuration selection in the older files without ModelHeader;
2. bounded dimension-placement layouts in place of the current scans;
3. the remaining display edge-type record and optional scalar arrays;
4. Block3 strip-control semantics;
5. LocalBodies and section-tail framing across the expanded online sample.

The zero-normal case, constant declaration bytes, unseen XT types and save/redraw behavior remain
blocked on inputs that differ in the required field or operation.
